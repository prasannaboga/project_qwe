topic: Add description field to Todo API
updated: 2026-08-22T12:24
---

- (note) Guided mode initiated for adding description field to existing Todo API
- (decision) Why accepted: Allow rich context on tasks while maintaining full backward compatibility
- (constraint) Description field is optional, nullable in DB, and capped at a maximum length of 1000 characters
- (constraint) Existing Todo records and API requests without description must continue to work seamlessly
- (capability) CAP-1: Create Todo with Description - client can provide optional description up to 1000 chars on POST /todos
- (capability) CAP-2: Retrieve Todo with Description - GET /todos and GET /todos/{id} include description string or null
- (capability) CAP-3: Update and Clear Description - update modifies text or clears to null when explicit null is provided
- (constraint) New forward-only Alembic migration required; existing migrations must not be modified
- (decision) Non-goals: No full-text search, no markdown parsing/HTML sanitization, no pagination/filtering additions, no file attachments
- (decision) Success Signal: CRUD operations support optional 1000-char description with 100% passing tests and applied Alembic migration

- (event) Self-Validate Pass 2 (Preservation): PASS on all source constraints and decisions
- (decision) Story breakdown agreed: Story 1 (Model & Migration) and Story 2 (Schemas, Service, API, Tests) with done_checkpoint enabled on each
- (event) Story validation: PASSED all schema rules for stories.yaml
